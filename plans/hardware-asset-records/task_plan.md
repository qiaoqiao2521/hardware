# 硬件资产清单与监控规划

## 目标

续接“对比RK3566与RK3568”会话，把提到的设备和已有历史体检整理到现有hardware仓库，形成可继续补充的资产清单和Frigate/HAOS计划。

## 当前需求

- 用户要求切换Work并继续长期硬件记录；当前工具没有切换模式入口，已提供官方入口说明。
- 用户补充“先全部列举”，因此完整列项，未知在手状态、数量与型号保留待核实。
- 续接“淘机评测分享”和“升级处理器建议”，补齐历史商品、惠普拆板、电源使用背景及官方规格限制；不将旧助手建议当成功能验收。
- 采用仓库现有SpecMesh和只读诊断边界，不为文档整理连接设备或部署服务。

## 计划与验收

1. 读取原会话、仓库入口与已有实体快照，区分用户原话、助手总结、历史体检及官方支持。
2. 保存资产总表、B68TK详细历史档案和Frigate/HAOS阶段计划，并链接README与PROJECT。
3. 检查日期、来源、链接、敏感内容和仓库遗留；保留未验证监控图片，串行合并既有提交。
4. 按既有授权提交推送，核对远端结果；生成本轮outputs下的可阅读副本。

验收：全部已提及设备可找到；ROCK 5C型号与软件兼容性边界明确；历史事实不被写为本轮实测；文档链接完整；提交、远端状态和未提交保留项有记录。
